# 읽기 순서 계산

PDF 내부 저장 순서 대신 시각적 읽기 순서를 계산한다 (`reading_order.py`).
원본 `block_index`와 계산된 `reading_order`를 모두 보존한다.

## 알고리즘

1. 텍스트 블록을 분류: 전체 폭(본문 폭의 72%↑ = 제목·초록 등) / 왼쪽 열 / 오른쪽 열 /
   각주(페이지 높이 87%↓에서 시작) / 중앙 걸침(→ 전체 폭으로 취급, straddler로 계수)
2. 좌·우 열이 모두 있고 걸침 비율이 낮으면 2단 판정
3. 전체 폭 블록이 세로 구간(band)을 나눈다:
   자기보다 완전히 위에 있는 separator의 수로 band를 정한다.
   band 안에서 **왼쪽 열(위→아래) → 오른쪽 열(위→아래) → 닫는 separator** 순서다.
   짧은 번호 표 캡션은 아래 조건을 모두 만족할 때만 추가 경계로 사용한다.

   - `표 2-9`, `Table 2`처럼 번호와 제목이 있고, 최대 96자·2줄이다.
   - 본문 좌측에서 페이지 폭의 6% 이내이며 전폭 블록이나 각주가 아니다.
   - 캡션 하단부터 40pt 이내에 시작하는 전폭 본문이 있다.
   - 캡션 위쪽을 가로지르는 본문이나 같은 높이의 독립 오른쪽 열이 없다.

   이 경계의 위쪽 좌표를 기준으로 기존 순서를 안정 정렬해 이전 표의 오른쪽 내용이
   다음 표 제목과 행 사이로 끼는 것을 방지한다. 구간 내부 순서는 유지한다.
   보정으로 순서가 바뀌면 신뢰도를 최대 0.5로 제한한다.

   번호가 첫 줄에 단독으로 추출된 절 제목(`2.` + 줄바꿈 + 제목)도 제한적으로 지원한다.
   좌측 정렬·전폭 본문 거리·각주 제외 조건은 같으며 다음 조건을 추가로 요구한다.

   - 최대 64자의 정확히 두 줄이며, 제목이 마침표·물음표 등 문장 종결 기호로 끝나지 않는다.
   - 위 본문과의 빈 간격이 제목 bbox 높이 이상이다. 높이가 0이면 보정하지 않는다.
   - 제목과 겹쳐 시작하는 다른 본문이 없고, 바로 아래 본문이 전폭이다.
   - 가장 가까운 시작 높이에 여러 블록이 있으면 모두 전폭이어야 한다.

   번호만 보고 일반 목록 전체를 절 제목으로 승격하지 않는다.
4. 단일 열은 위→아래(같은 높이는 왼→오), 각주는 항상 페이지 마지막
5. 표 내부 텍스트 블록은 `is_table`로 표시해 본문(normalized_text)에서 중복 제외

## 지원 범위·한계

지원: 단일 열 · 좌우 2단 · 전체 폭 제목+2단 · 하단 각주 · 표/그림 캡션.
완벽한 문단 복원은 가정하지 않는다 — 걸침이 많으면
`reading_order_confidence`를 0.5로 낮추고 GUI 안내 탭에 "읽는 순서가 정확하지 않을 수
있는 페이지"로 표시한다. 3단 이상·L자 흐름·표 안 다단은 미지원(순서 신뢰도 하락).

위 보정은 모든 절 제목이나 표의 행·열 관계를 복원하지 않는다. 한 줄 번호 제목,
로마 숫자·괄호형 번호, 간격/배치 근거가 부족한 제목은 기존 순서를 유지한다.
원문·bbox·block_index는 변경하지 않으며 새 추출의 reading_order와 경계 메타데이터에 반영한다.
이미 저장된 문서는 설치만으로 재추출하거나 청크를 재생성하지 않는다.
실제 저장 좌표의 읽기 전용 재계산과 한계는
[표 캡션 경계 검증](../testing/qa-table-caption-order-20260912.md)과
[번호 절 경계 검증](../testing/qa-section-order-20260912.md)에 기록한다.

## 검증된 절 경계의 청크 전달

`OrderResult.section_heading_indices`는 위 배치 조건을 모두 통과한 번호 절 제목의
원래 block_index만 담는다. 표 캡션은 포함하지 않으며 단일 열은 기존 규칙을 유지한다.
입력 순서가 이미 맞아 재정렬이 없어도 검증된 절 경계는 반환한다.

추출 파이프라인은 표·캡션으로 분류되지 않은 해당 블록에만
`metadata_json.section_boundary: true`를 저장한다. 기존 JSON 컬럼을 사용하며
스키마 변경·기존 문서 역채움·자동 재추출·자동 청크 교체는 하지 않는다.

청크 생성기는 디지털 TEXT 블록의 정확한 boolean `true`만 명시적 절 경계로 사용한다.
표 청크와 머리말·꼬리말·저신뢰 OCR 제외 규칙은 유지한다. 경계 앞의 병합 후보를 닫아
제목이 같은 짧은 절도 페이지 batch를 넘어 다시 합치지 않는다.
제목 원문과 출처는 보존하며, 일반 여러 줄 본문에 대한 기존 제목 휴리스틱은 바꾸지 않는다.

메타데이터 없는 기존 추출 결과는 청크만 다시 만들어도 이 보정이 적용되지 않는다.
전체 검색·답변 효과는 별도 검증 대상이다.
[저장·청크 재생성 회귀와 실제 좌표 비교](../testing/qa-section-chunk-boundary-20260912.md).
