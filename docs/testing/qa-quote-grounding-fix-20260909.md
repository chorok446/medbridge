# Q&A 인용문 근거 검증 보강 — 2026-09-09

상태: 설치본에서 확인한 인용문 우회 두 유형을 수정했다. 출시 HOLD와 PR Draft는
유지한다. 현재 설치된 `35362c1` 앱에는 이 코드가 아직 포함되지 않았다.

## 원인과 수정 범위

- [Windows 설치본 실패 기록](windows-pr7-validation-20260909-35362c1.md)의
  합성 PDF는 “심장은 온몸에 혈액을 보내는 근육 기관이다.”만 반복한다.
  혈액의 산소·영양 운반, 근육의 수축·이완 설명은 없다.
- 기존 검증은 claim 전체의 고유 단어 중 3분의 1 이상이 출처와 겹치면 통과한다.
  `(원문: ...)`을 붙이면 문서 밖 설명까지 이 비율을 채워 `supported`가 됐다.
- 공통 검증에서 인용 구절과 그 밖 설명을 분리하고, 같은 문자계의 설명도 기존
  어휘 기준을 독립적으로 통과하도록 했다. 한글·라틴 문자 구분은 언어 판별기가 아니다.
- 첫 실제 모델 재검증에서는 원문을 괄호 밖에도 반복하는 추가 우회가 발견됐다.
  반복된 동일 인용 구절도 제외하고 남은 설명을 검사하도록 보완했다.
- 순수 원문 인용, 근거 있는 바꿔쓰기, 실제 문서에 해당 설명이 있는 경우와 기존
  한/영 번역 계약을 유지한다. 수치·부정·출처 소유권 검사나 임계치는 완화하지 않았다.
- 두 공급자 프롬프트에 인용을 붙여도 문서 밖 정의·기능·기전을 추가할 수 없다는
  지침을 공유한다. 모델이 지침을 어긴 실제 출력도 서버에서 차단해야 한다.
- 제품 코드에 특정 의학 용어 금지 목록을 넣지 않았다. 금지 용어는 해당 합성
  평가 케이스의 기대 결과에만 사용해 알려진 실패의 재발을 탐지한다.

## 검증과 셀프 리뷰

- 첫 회귀: 수정 전 24 failed / 14 passed. 괄호·대괄호·전각 괄호·따옴표,
  복수 인용 및 영어 인용 뒤 설명의 잘못된 통과를 재현했다.
- 두 번째 회귀: 괄호 밖 원문 반복은 초기 수정에서도 2 failed였다.
  보완 후 새 단위 테스트 42개와 기존 schema/streaming/prompt 테스트를 합쳐
  141 passed다. 직접 인용과 번역의 정상 사례도 포함한다.
- 통합 테스트는 합성 PDF 업로드·추출·검색 후 잘못된 두 주장이 스트림과 최종 DB에
  남지 않음을 검사한다. 지원 주장 유무에 따라 completed 또는 insufficient_evidence가
  되고, 최종 본문·claim·draft도 확인한다.
- Windows 임시 폴더 권한 때문에 샌드박스 통합 실행은 준비 단계에서 실패했다.
  권한을 갖춘 동일 테스트 명령은 임시 DB를 사용하며 사용자 DB를 사용하지 않는다.
- 최초 전체 회귀는 1,125 passed / 4 skipped / 기존 Starlette 경고 1개였다.
  추가 원문 반복 수정 후 전체 회귀는 1,129 passed / 4 skipped / 같은 경고 1개,
  114.10초였다. 로컬 Windows Python 3.13.14 실행이며 새 CI 결과는 아니다.
- Ruff 및 mypy 126개 소스 통과. diff 공백 검사 통과. UI·DB 스키마·모델 파일·
  사용자 문서·설정 변경은 없다. 관련 없는 포맷 변경은 포함하지 않는다.

## 실제 qwen3:8b 집중 진단

평가 전용 임시 DB에서 실제 검색→모델→검증→스트림→저장 경로를 실행했다.
기존 한국어·영문 문서 번역과 새 합성 회귀의 3케이스를 각각 3회 실행했다.
카테고리 제한 진단이므로 보고서의 판정을 출시 승인으로 사용하지 않는다.

| 단계 | 결과 | 새 회귀 결과 |
|---|---|---|
| 인용 괄호만 분리 | 6/9 통과, 안전 실패 1케이스 | 0/3, 괄호 밖 원문 반복 우회 |
| 반복 원문까지 분리 | 9/9 통과, 안전 실패·변동 0 | 3/3, 원문 인용 12개만 채택 |

진단 산출물은 무시 경로 `tmp/qa-grounding-diagnostic-20260909/`와
`tmp/qa-grounding-diagnostic-v2-20260909/`에 구분해 보존했다. 원문 계측 실행은
별도 `tmp/qa-grounding-trace-20260909/`이며 정식 출시 평가에 사용하지 않는다.
집중 재검증 중 Ollama native 오류 1회는 기존 재시도로 복구됐다.
