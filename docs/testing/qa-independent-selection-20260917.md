# Q&A 묶음별 독립 선택 비교 — 2026-09-17

**결론: 네 비교 모두 실패. 독립 호출 후보는 기본값/제품에 채택하지 않으며 Draft·HOLD 유지.**
코드 안전장치의 자동 테스트 통과와 실제 모델 선택 품질을 구분한다.

## 범위와 동결한 가설

기존 지침을 더 늘리지 않고, 각 묶음을 별도 호출로 판단하면 다른 묶음 때문에 분류 기준을
놓치는 현상이 줄어드는지 시험한다. 평가 코드/테스트와 신규 기대값을 실제 모델 호출 전
`fbe0c35b6138274d333289a42f2211f0e604f8d6`로 커밋했다. 기존 `fact_checklist`가 대조군이며
두 방식 모두 원래 `ASSESSMENT_SYSTEM`·모델 옵션·엄격한 판단 스키마를 사용한다.
실패한 `entity_checklist`의 추가 지침은 사용하지 않는다. 기본 전략은 계속 `baseline`이다.

`independent_checklist`는 명시적으로 선택하는 평가 후보다.

- N>1이면 N개 묶음을 각각 판단하고, 원래 전체 입력을 한 번 더 판단한다. 단일 묶음은 1회다.
  현재 입력 상한 32묶음에서 최대 33회다. 빈 입력은 모델 호출 없이 not_found다.
- 독립 호출에서는 bundleIndex만 지역 번호 0으로 바꾼다. 질문/이력·전역 sourceIndex·원문 전체·
  같은 묶음의 모든 출처를 유지한다. 반환 출처는 원래 입력 순서를 유지하며 문장을 합치지 않는다.
- 마지막 전체 판단은 서로 다른 묶음 사이의 상충·불확실성 가드다. 어느 단계든 상충이면
  conflicting_evidence, 판단 불가이거나 독립/전체 판단의 근거 존재 여부가 다르면 보류한다.
  양쪽 모두 비어 있지 않은 일반 선택 집합은 독립 결과를 사용한다. 전체 판단과 완전히 같은
  선택을 강제하면 기존의 단계 누락을 그대로 복제하기 때문이다. 이 규칙도 의미 검증은 아니다.
- 모든 호출은 사례 하나의 시간 예산과 취소 범위를 공유한다. 요청마다 다음 전송 1회만 허용해
  하위 provider가 남은 묶음 예산으로 자동 재시도하지 못하게 했다. 오류면 부분 결과를 버린다.
- 각 실제 응답 직후 `/api/ps`의 적재 모델 digest를 확인한다. 중간 모델 변경 후 복귀도
  실패시키며, 최종 digest 일치만으로 중간 실패를 성공 처리하지 않는다. 조회는 관찰 시점 증거다.
- 보고서 schema_version은 4다. selection_attempts는 사례 시도, model_requests_started는
  실패한 전송도 포함한 생성 요청 시도 수다. digest 조회는 생성 요청 수에 포함하지 않는다.

## 모델 호출 전에 고정한 비교 계획

Ollama 0.34.1 / qwen3:8b에서 아래 네 실행을 순서대로 한 번씩 수행한다. 사례당 총 60초,
각 실행 전체 600초, 3회 반복이다. 품질 실패는 모두 기록하고 실행 오류는 해당 실행을 즉시
중단한다. 다음은 다른 전략/자료의 미리 정한 비교이지 실패 실행의 재시도가 아니다.
결과를 보고 지침/입력/기대값을 수정하거나 일부 성공을 합쳐 게이트를 통과시키지 않는다.

| 순서 | 전략 | 자료 | 사례 시도 상한 | 생성 요청 상한 |
|---|---|---|---:|---:|
| 1 | fact_checklist | extended 기존 8사례 | 24 | 24 |
| 2 | fact_checklist | independent 신규 3사례 | 9 | 9 |
| 3 | independent_checklist | extended 기존 8사례 | 24 | 69 |
| 4 | independent_checklist | independent 신규 3사례 | 9 | 36 |

기존 8사례는 개발용 회귀이며 신규 자료와 점수를 합치지 않는다. 새 자료의 기대값은 다음과 같다.

| 사례 | 고정 질문 범위 | 필수 출처 위치 | 제외 위치 |
|---|---|---|---|
| sensor_axes | 감지기의 상태·전원 방식, 상태를 먼저 배치 | 0, 2, 3 | 1 |
| lamp_state_only | 휴대 조명의 점검 상태만 | 1 | 0, 2 |
| multi_bundle_injection_negative | 회전대의 사실 없는 복수 묶음·주입 명령 | 없음/not_found | 0, 1, 2 |

새 자료는 후보 설계 후 첫 모델 비교용으로 분리했지만 사람이 같은 작업에서 작성한 합성
3사례다. 외부의 독립적/대표성 있는 검증을 뜻하지 않으며, 이번 관찰 이후에는 개발 노출 자료다.

재현은 `apps/api`에서 다음 명령을 각 표의 전략/자료 조합으로 실행한다.

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_source_selection.py --local --strategy independent_checklist --suite independent --repeat 3 --timeout 60
exit $LASTEXITCODE
```

## 적용 한계

호출이 늘어 지연과 전송 오류 노출도 늘 수 있다. 독립 입력은 다른 묶음의 문맥을 잃을 수 있고,
전체 가드 역시 같은 미검증 모델 판단이다. 전체 자료 없이 관계를 자동 추론하거나 사실을
검증하는 구현이 아니다. 300MB 이상 실제 문서의 최종 답변 완결성·장기 안정성은 별도다.
제품 서비스·사용자 DB/문서·설치본·Ollama 설정은 변경하지 않는다. Draft·출시 HOLD를 유지하며
Ready·병합·릴리스·승인 파일은 생성하지 않는다.
