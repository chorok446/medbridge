## 별도 상충 안전성 수정 — 193babd

앞선 `a9d945e`의 첫 전체 평가는 38/39였다. 상충 사례 첫 회에 두 주장 중 하나가
`no_valid_source`로 거부된 뒤 completed가 됐다. 당시 원시 ID와 final 힌트는
미수집이므로 **그 실패의 정확한 원인을 이번 합성 재현으로 확정하지 않는다.**

별도로 확인한 코드 경계는 명확하다. 모델이 `conflicting_evidence`를 보내도 지원
주장이 하나만 남으면 batch/stream 최종화가 completed로 흘렀다. 이를 각각 한 조건으로
보강해 지원 주장 2개 미만이면 `insufficient_evidence`로 보류한다.

- 출처를 추측하거나 미상 ID를 정상 ID로 바꾸지 않는다. 수치·어휘·극성·출처 검증,

## 고정 전체 모델 평가와 한계

기존 로컬 `qwen3:8b` / Ollama 0.33.3, clean tree의 `193babd`로 전체 데이터셋
13개 × 3회 = **39/39**를 통과했다. exit 0, `default_recommended`,
명시적 위해·안전 중요 실패·변동 0이다. 모든 카테고리 100%이며
p50 2.922초 / p95 29.230초다. 설치 앱과 읽기 전용 보존 점검이 병행된 추적 환경이므로
이전 평가와의 성능 개선/회귀 비교로 해석하지 않는다.

모델 digest는 실행 전후 같고 다음과 같다.

`sha256:500a1f067a9f782620b40bee6f7b0c89e17ae61f686b92c24933e4ca4b2b8b41`

- 루트의 임시 진단 래퍼 `tmp/trace-conflict-abstention.py`가 기존 평가기를
  `--model qwen3:8b --repeat 3 --fail-on-gate --keep-failed-artifacts`로 호출했다.
  출력은 `artifacts/qa-evaluation/20260910-conflict-abstention`에 보존했다.
- 실제 서비스의 검색→공급자→검증→저장 경로와 Git/모델 실행 경계 검사를 유지했다.
  **계측 없는 평가가 아니라 상충 사례만 원시 출력을 제한 수집한 전체 평가**다.
  사용자 DB 대신 합성 자료 전용 임시 DB를 사용했고, 진단용으로 보존했다.
- 합성 `conflict_mortality` 시도만 content를 최대 8,192자 수집하고 파싱·done 프레임·
  최종 힌트·검색 청크를 함께 기록했다. 사용자 문서·키·프롬프트 본문을 수집하지 않았다.
  공개 추적 JSON의 합성 UUID는 일관된 별칭으로 바꿨다.
- 상충 3/3: 검색 2청크·지원 claim 2개·거부 0·conflicting_evidence.
  각각 정상 claim/claim/final과 done 1개가 확인됐다. 이전 잘못된 ID는 재현되지 않았다.
- native error frame 3회, HTTP 500 1회가 기존 재시도에서 복구됐다.
  미완결 시도 claim은 폐기됐으며 평가를 처음부터 다시 돌려 실패를 없애지 않았다.
  시작 전 preflight 실패는 이번 실행에 없었다.

  이번 가드로 식별할 수 없다. 일반 의미 정확성이나 모든 모델 오류를 해결했다고 주장하지 않는다.
- 안전한 보류가 필요한 상황에서 보류하는 회귀와, 정상 양쪽 근거를 생성하는 모델 품질 평가는
