- 현재 문서에서 검색한 `QaRequest`와 `QaChunkRef` 스냅샷을 입력으로 받는다.
  모델은 원문을 재작성하지 않고 각 입력 번호의 포함/제외만 결정한다.
- 모든 입력 번호를 JSON 객체의 필수 키로 둔다. 값은 true/false 모두 허용한다.
  누락·미상 번호·중복 키·문자열/정수 대신 boolean이 아닌 값·추가 산문은 거부한다.
  누락된 판단을 false로 채우거나 잘못된 ID를 추측 복원하지 않는다.

  복사한다. 모델 출력 순서로 떨어진 행을 한 문장으로 합치지 않는다.
  가시 텍스트가 원본의 일부면 `input_truncated`와 원본 내 시작/끝 위치를 남기며,
  모델에게 보이지 않은 뒤쪽 원문으로 늘리거나 claim 600자 상한으로 자르지 않는다.
- 위치·파일명·원본 ID는 모델 입력에 넣지 않는다. 입력 번호는 요청 스냅샷 안에서만
  원래 ID에 대응한다. 해시와 source_refs는 서버에 남는 출처 정보다.
- 고정 loopback Ollama·허용 모델만 사용한다. 기존 안전 HTTP·취소·입출력 절단 검사와

## 실제 질문 비교 — 실패를 포함한 22회

431,634,439바이트·1,060쪽 익명 문서 `large-1`의 원래 긴/짧은 질문과 6/7턴 이력을 유지했다.
모든 실행은 32개 동일 입력 청크와 같은 설치·적재 qwen3:8b digest를 사용했다.
모델 답변을 사용자 대화로 저장하지 않고 원문 선택 결과만 읽기 전용으로 측정했다.

| 단계 | 호출 | 결과 | 판단 |
|---|---:|---|---|
| 원래 ID 목록만 선택 | 6 | 모두 청크 1개, 280자 | 후속 항목 누락, 미채택 |
| 입력별 판단 배열 | 6 | 모두 invalid_output_sources | 전체 판단 형식 불충족, 미채택 |
| 배열 실패 계측 | 2 | 필요한 32개 중 번호 7 판단 1개만 반환 | 누락 위치 확인, 부분 응답은 거부 |
| 모든 번호가 필수인 판단 객체 | 6 | 긴 질문 청크 1개, 짧은 질문 2개 | 형식 통과, 완결성 실패 |
| 최종 모듈 확인 | 2 | 같은 1개/2개 선택 재현 | 평가용으로만 보관 |

- 필수 객체 방식의 긴 질문은 입력 번호 7(280자), 짧은 질문은 2·7(290자)을 골랐다.
  선택된 원문·해시·좌표는 입력과 일치하고, 독립 발췌는 기존 claim 검사도 통과했다.
  다만 짧은 질문의 추가 청크는 제목이다. 지원 개수 증가를 유용한 답변 증가로 세지 않는다.
- HFpEF와 NYHA 표지의 선택은 모두 0이다. 해당 근거가 입력에 있어도 선택에서 빠졌다.
  필수 판단을 채웠다는 사실을 모델이 올바르게 이해했다는 증거로 간주하지 않는다.
  별도 무생성 입력 확인에서 두 질문 모두 HFpEF는 번호 8, NYHA는 18에 있었다.
  번호 8은 600자가 넘으므로 선택되더라도 기존 claim으로 그대로 잘라 내보낼 수 없다.
- 기존 자료에는 표 제목과 후속 항목이 서로 다른 청크에 있고 일반 설명도 섞여 있다.
  이것이 모델 누락의 유일한 원인이라고 입증한 것은 아니다. 다음에 행·제목 관계를
  원문 블록/좌표로 확인할 필요가 있다는 근거다.
- 첫 실험의 도구 출력에서 한국어 지표 키만 인코딩이 잘못 표시됐다. 고정 helper의
  키를 확인해 공개 지표에는 `classification`으로 기록했다. 이후 출력은 UTF-8/ASCII JSON이다.
- 이전 일반 답변 생성 실험과 이번 후보 선택 실험은 출력 계약이 다르므로 지원 수나
  응답 속도를 직접 우열 비교하지 않는다. 반복/캐시가 포함된 시간은 성능 벤치마크가 아니다.

[익명 지표 JSON](qa-evidence-selection-prototype-20260912.json)은 원문·생성 산문·내부 ID 없이
입력 번호, 상태, 개수, 시간, 모델 및 보존 해시만 공개한다.
