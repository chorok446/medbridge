## 원인과 단일 변경 범위

직전 `df67118`은 두 줄 번호 절 제목의 읽기 순서를 바로잡았지만 청크 생성기는
줄바꿈이 있으면 제목으로 보지 않았다. 따라서 위쪽 표의 마지막 내용과 새 절이
같은 청크에 남았다. [이전 재현과 한계](qa-section-order-20260912.md).

읽기 순서 계산의 이미 검증된 절 인덱스를 `OrderResult.section_heading_indices`로 반환하고,
추출 파이프라인에서 해당 블록의 JSON에 `section_boundary: true`를 저장한다.
표·캡션으로 별도 분류된 블록은 제외한다. 표 캡션의 읽기 순서 보정 자체는 유지한다.
경계 정보는 재정렬이 없어도 반환하며 단일 열의 감지 범위를 확대하지 않는다.

청크 생성기는 디지털 TEXT 블록의 정확한 boolean true만 절 경계로 사용한다.
기존 병합 후보를 경계 앞에서 마감해 제목이 같은 짧은 절도 페이지 batch를 넘어
재병합하지 않는다. 제목 원문·출처 ID·bbox·reading_order는 보존한다.

- 모든 줄바꿈을 지우는 대안은 일반 여러 줄 본문을 제목으로 오인하므로 제외했다.
- 메타데이터 없음/false/문자열/숫자는 기존 제목 휴리스틱을 따른다.
- 표 청크와 머리말·꼬리말·디지털/OCR 선택 규칙은 유지한다.
- DB 스키마·모델·프롬프트·검색 상한·출처 검사·평가 게이트는 변경하지 않는다.
- 기존 문서 역채움·자동 재추출·활성 청크 교체·설치·모델 호출은 하지 않는다.
