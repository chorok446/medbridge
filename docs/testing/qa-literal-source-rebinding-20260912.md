# 전체 원문 인용의 출처 연결 복구 — 2026-09-12

제품 커밋: `9cc6414`. PR 7 Draft·출시 HOLD 유지.
**짧은 전체 청크 인용의 ID 혼동만 보강했으며 실제 분류 답변의 수치 오류 4건은 미해결이다.**

## 재현과 수정 범위

지난 전체 문서 비교에서 거부된 수치가 다른 검색 청크에는 있어도, 그 사실만으로 올바른
의미상 출처를 확정할 수 없었다. 기존 수치 검사는 정상적인 방어이므로 완화하지 않는다.

합성 장치 문서에서 다음 좁은 하위 사례를 재현했다. 전압 청크 전체를 그대로 인용하면서
출력 청크의 실제 ID를 붙이면 기존 연속 인용 복원은 원래 ID가 포함된 범위만 찾아 실패한다.
최초 새 단위 검사 결과는 **5 failed / 23 passed**였다.

새 복구는 다음 조건을 모두 만족해야 한다.

- 이번 검색에 실제로 있는 ID가 제공돼야 한다. 빈 ID·미상 ID를 새로 만들어 주지 않는다.
- 문장은 정규화 후 24자 이상, 원래 문장과 대상 청크는 각각 600자 이하여야 한다.
- 문장 전체가 청크 전체와 일치해야 한다. 기존 NFKC·공백 정규화만 사용한다.
  부분 인용, 재서술, 인용 표시 제거, 단위 교체, 추가 설명·조건 생략을 보정하지 않는다.
- 후보 ID와 출처 ID가 같고, 유효한 단일 페이지·연속 읽기 순서가 있어야 한다.
- 모델 가시 범위에 같은 문장을 포함한 다른 청크나 기존 최대 네 청크 연속 인용 대안이
  없어야 한다. 같은 시작 위치의 후보가 겹쳐 유일성을 판단할 수 없어도 교체하지 않는다.
- 이미 해당 출처를 인용했다면 순서·출처 집합을 변경하지 않는다.
- 복구 뒤에도 기존 수치·어휘·부정·질문별 검증을 거친다. 전체 검색의 숫자로 대신 검사하지 않는다.

문장·청크 원문·해시·좌표는 변경하지 않고 출처 ID와 저장된 출처 참조만 재구성한다.
기존 여러 청크 순수 인용의 누락 ID 완성은 유지한다. 검색량·프롬프트·모델·네트워크 재시도,
DB 스키마·문서 재처리·설치본·기존 사용자 대화에는 변경이 없다.

## 검증과 최초 실패 기록

- 새 단위 **30개**, 합성 PDF 업로드→추출→청크 생성→검색→응답/저장 통합 **4개**를 추가했다.
  일괄/스트리밍 모두 원문 전체만 복구하고 재서술은 계속 제외한다. 정정한 쪽수·블록·좌표와
  ID가 응답 및 저장에 반영되며, 청크 텍스트·해시·출처 스냅샷이 유지된다.
- 중복/부분/숨은 원문·잘린 문장·단위/부정 변경·미상 ID·불명확한 위치·연속 대안은 복구하지 않는다.
  NFKC 비교로 일치하더라도 기존 수치 검사에서 거부될 수 있음을 별도 확인했다.
- 관련 검사 **74 passed**, 1.99초. 전체 API **1,583 passed / 4 skipped**, 117.83초.
  Ruff 통과, mypy 131개 소스 통과, diff 검사·변경 파일 LF 확인 완료.
  기존 접근 불가 캐시 폴더 경고와 Starlette/httpx 사용 중단 예정 경고는 변경하지 않았다.
- 최초 통합 검사 **4 failed / 70 passed**: 제목 없는 짧은 두 본문이 페이지를 넘어 하나로
  합쳐져 가짜 공급자가 두 출처를 찾지 못했다. 저장된 합성 원문을 확인해 원인을 확정했다.
  제품 청크 규칙을 바꾸지 않고 PDF의 두 번째 절에 실제 제목을 넣어 두 출처를 구성했다.
- 그 다음 **2 failed / 2 passed**: 통합 테스트가 최종 응답 필드를 `sources`로 잘못 조회했다.
  기존 공개 계약의 `sourceRefs`로 검증 코드를 고쳤다. 이후 관련·전체 검사는 통과했다.
- 디버깅 스킬의 재현→원인 분리→회귀 검증 절차를 따랐으며 실패를 건너뛰거나 검사를 완화하지 않았다.
  통합 시험 자료는 일회용 테스트 DB에 격리했다. 실제 모델/GUI 실행은 이번에 하지 않았다.

## 기존 실제 실패 기록의 오프라인 재검증

이전 1,060쪽 격리 사본을 `mode=ro`·`query_only=ON`으로 열고 저장된 생성 기록만 재검증했다.
두 질문의 검색 청크 수·문자 수 및 모든 원래 인용 ID의 존재를 확인했다.
원문·숫자 값·실제 ID는 출력하지 않았으며 설치 DB에는 접근하지 않았다.

|---|---:|---:|---:|---:|
| 긴 분류 질문 | 5 | 2 / 3 | 2 / 3 | 0 |
| 짧은 분류 질문 | 5 | 4 / 1 | 4 / 1 | 0 |

모델 새 호출 **0회**, DB 쓰기 **0회**. 기존 오류는 이번 전체 원문 일치 복구 조건에 해당하지
않는다. 숫자가 다른 검색 청크에 있다는 이유로 연결하거나 통과시키지 않았다.
이는 저장된 두 응답의 오프라인 확인이며 신규 생성 성능·분류 완결성·의미 정확성 평가는 아니다.
