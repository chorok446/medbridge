# Q&A 원문 인용 형식과 문단 누락 회귀 — 2026-09-09

## 재현과 선택한 수정

- [dc27530 설치본](windows-pr7-validation-20260909-dc27530.md)에서 긴 질문의
  새 대화 3회 중 2회가 전체 보류됐다. 같은 출처의 중복 출력은 별도 수정
  `25235ad`와 [중복 제거 기록](qa-stream-dedup-20260909.md)으로 분리했다.
- 설치본의 합성 PDF에 해당하는 활성 청크 1개만 읽기 전용으로 가져와 실제
  qwen3:8b provider와 기존 claim 검증기로 같은 긴 질문을 3회 진단했다.
  원문은 `심장은 온몸에 혈액을 보내는 근육 기관이다.`의 문단 1~12 반복이다.
  사용자 문서 원문·DB·자격증명을 로그나 저장소에 게시하지 않았다.
- 수정 전 매회 17개 claim 중 채택 0개였다. 문서 밖 단어 정의 5개뿐 아니라
  원문 인용 12개도 `문단 N은 ...라는 문장을 반복하여 기술하고 있다` 같은
  소개 설명을 포함했다. 인용 구절을 제외한 설명의 어휘가 근거에 없어 거부됐다.
  1회에는 출처 ID 오타도 있었다. 관측한 provider 이벤트에 final은 없었다.
- 같은 원문과 질문에서 순수 인용 형식 지침만 추가한 실험은 3회 모두
  원문 인용 12개 채택, 문서 밖 정의 5개 거부, final answered였다.
  실행 시간은 20.477 / 20.004 / 19.618초다. 원래 지침의 시간은
  23.417 / 21.744 / 24.574초이며 일반적인 성능 개선 수치로 해석하지 않는다.
- 공유 지침에 문서에 있는 문단 번호와 문장을 `문단 N: 원문 문장` 형식으로
  인용하고 소개 설명·같은 원문 괄호·문서 밖 정의를 덧붙이지 않도록 명시했다.
  비스트림·스트림 경로 모두 같은 지침을 사용한다. 문단이 다르면 각각 보존한다.
- 어휘 임계치·출처·수치·극성 검증과 최종 보류 정책은 바꾸지 않았다.
  소개 설명을 통과시키려고 검증을 완화하는 대안은 채택하지 않았다.
  모델은 새 지침에도 문서 밖 정의를 생성했으므로 서버 검증은 계속 필요하다.

## 회귀 검사

- 새 프롬프트 계약 테스트는 수정 전 실패했고, 수정 후 양쪽 provider의 공유
  지침 적용을 확인했다. 기존 인용 근거·schema·streaming·manifest를 합친
  집중 단위 테스트 155개와 Ruff·mypy 126개 소스가 통과했다.
- 기존 합성 평가 사례에 expectedNumbers 1~12를 추가했다. 문단 인용 1개만
  남아도 통과하던 이전 평가의 빈틈을 좁힌다. 안전 기준은 그대로 유지했다.
- 평가기 회귀는 문단 1개일 때 안전 중요 실패, 12개일 때 통과를 확인한다.
  번호 포함 여부만 검사하므로 각 번호와 문장의 대응·순서까지 보장하지 않는다.
- 모의 provider는 청크 앞 200자만 출력하므로 강화된 문단 조건을 충족하지 못한다.
  통합 회귀는 이 불완전 응답의 expected_numbers 실패와 게이트 차단을 명시적으로
  검사하며, 다른 기본 근거 사례의 통과도 유지한다. 실제 모델 기준은 완화하지 않는다.
- 중복 제거 직후 전체 API 실행은 1 failed / 1,129 passed / 4 skipped였다.
  `TestPull.test_yields_events_and_skips_nonjson`의 모의 서버 연결에서
  connect_failed가 났다. 무수정 단독 재실행은 1 passed / 0.60초였으며
  다음 전체 실행에서도 이 테스트는 통과했다. 일시 실패의 근본 원인은 미확정이다.
- 프롬프트·문단 조건 추가 후 전체 실행은 1 failed / 1,131 passed / 4 skipped,
  101.97초였다. 실패는 모의 응답도 모두 완성됐다고 가정한 기존 평가 통합
  테스트였고, 위의 불완전 응답 차단 회귀로 기대 동작을 구체화했다.
- 평가 단위·통합 집중 회귀는 29 passed / 3.28초다. 최종 API 전체는
  **1,132 passed / 4 skipped / 기존 Starlette 경고 1개**, 103.08초다.
  Windows Python 3.13.14이며 CI의 Python 3.12 검사와 구분한다.
  Ruff 전체 검사와 mypy 126개 소스도 통과했다. 읽기 권한이 없는 기존 임시
  pytest 캐시 디렉터리 2개는 Ruff 경고로 남았으며 이번에 삭제·변경하지 않았다.
- 고정 커밋 전체 모델 평가는 후속 결과에 구분해 기록한다.
