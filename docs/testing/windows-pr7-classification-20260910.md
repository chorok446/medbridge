## 사용자 화면과 수정 전 원인

사용자가 보낸 화면에서는 정의 답변 이후 두 분류 질문이 모두 근거 부족으로 끝났다.
비공개 자료는 `large-1` 별칭만 사용한다: 431,634,439 bytes / 1,060쪽 /
활성 청크 16,239개 / revision 17. PDF 138~139쪽에 관련 근거가 존재한다.

- 긴 요청은 검색어가 `심부전 분류에 대해`로 남아 요청 표현이 OR 검색을 오염시켰다.
- 짧은 요청은 `심부전`만 남아 별도 분류 의도가 검색 우선순위에 반영되지 않았다.
- 기존 제목 뒤 +8청크 범위는 +9 위치의 표 후속 조각과 여러 짧은 청크 뒤의
  다음 쪽 분류 설명을 놓쳤다. 전체 문서 미추출이나 JSON 파싱 실패로 단정하지 않는다.
- 수정 전 원래 이력을 사용한 읽기 전용 재생에서 긴 요청은 지원 2개·거부 2개로 완료,
  짧은 요청은 claim 4개 모두 출처 ID가 없어 `no_valid_source`로 거부됐다.
  원래 GUI 실패의 원시 응답은 저장되지 않았으므로 이 재생과 정확히 같았다고 확정하지 않는다.

## 목적별 변경

### 110d9c2 — 분류 표 후속 근거

- 요청 표현의 조사와 `대해/대한/관해/관한`을 정리하고 분류 의도를 별도 보존한다.
  `분류`를 문서 전체 OR 검색에 추가해 무관한 분류를 긁어오는 방식은 사용하지 않는다.
- 주제와 정확히 일치하는 절 제목이 있고 실제 출처가 한 쪽으로 식별되는 경우에만,
  같은 문서·generation의 제목 -3~+64 범위, 실제 현재/다음 쪽 출처를 후보로 삼는다.
- 분류 표지 최대 4개 주변 -12~+8 조각을 읽기 순서대로 먼저 선택한다.
  나머지는 기존 검색으로 보충하며 최대 32청크·12,000자·청크당 3,000자 제한을 유지한다.
- 원문·출처 ID·해시·좌표를 재작성하지 않는다. 다중 쪽에 재사용된 제목,
  비활성 generation, 범위만 겹치는 가짜 페이지, 먼 청크는 새 우선 수집에서 제외한다.
- 정확한 절 제목이 없으면 기존 검색으로 돌아간다. 절 계층 전체를 이해하거나
  다음 쪽의 다른 주제를 완전히 구분하는 일반 검색 해결책은 아니다.
- 합성 회귀는 수정 전 5 failed / 14 passed, 수정 후 기존 검색까지 포함해 30 passed다.

### 7628f44 — Windows 모의 서버 EOF 보정

전체 검사에서 기존 `test_yields_events_and_skips_nonjson`이 WinError 10054로 실패했다.
첫 전체 결과는 1 failed / 1,360 passed / 4 skipped이고, 동일 단독 시험을 세 번 새로
실행했을 때 통과/통과/동일 실패를 재현했다. 이 실패 기록을 후속 성공으로 지우지 않는다.

유한한 NDJSON을 보내는 모의 서버가 Content-Length 없이 연결 종료에 의존했다.
UTF-8 byte 길이를 헤더에 명시하고 기존 줄별 flush·20ms 지연은 유지했다.
새 회귀는 한글 응답을 7-byte read1로 EOF까지 20회 읽는다. 관련 26개 통과다.
제품 네트워크 오류를 무시하거나 테스트의 대기 시간을 늘린 변경은 아니다.
