## 시험한 방식과 적용 경계

기존 생성 문장은 검색된 여러 청크 중 실제로 근거가 없는 ID를 붙일 수 있었다.
전체 원문 인용의 제한적 복구는 재서술 문장에 적용할 수 없으므로 생성 입력을 분리했다.

- 한 번에 완전한 청크 하나와 독립 질문만 모델에 보낸다. 다른 청크·이전 대화·ID·쪽수·
  제목 메타데이터를 보내지 않는다. 이력이 있거나 청크가 잘렸으면 호출 전에 거부한다.
- 모델은 상태와 재서술 문자열 목록만 반환한다. 서버가 입력 스냅샷의 출처를 고정하며,
  해당 청크 하나만 대상으로 기존 수치·어휘·부정·정의 검사를 적용한다.
- 원문 전체·해시·좌표·읽기 순서와 출처 ID를 복사해 후보에 연결한다. 서로 다른 청크의
  숫자로 근거를 보충하거나 본문/해시를 바꿔 출처를 만들어 주지 않는다.
- 결과는 `candidate_texts`와 `rejection_reasons`다. 모델의 `rewritten`은 완료·지원 상태가
  아니다. 하나라도 후보가 남았다는 이유로 완전한 답변으로 저장하거나 표시하지 않는다.
- 3,000자 입력·600자 문장·20개 출력 상한, 완전한 JSON·보류/상충 상태를 검사한다.
  JSON 문법의 길이 제한으로 문장을 강제 절단하지 않고 초과 출력을 거부한다.
- 고정 loopback Ollama·허용 모델만 호출한다. 1회 요청 예산, 최대 600초, 취소/입력 변경/
  잘린 전송 가드를 사용하며 자동 재시도·다운로드·설정/DB 쓰기는 없다.

이는 평가용 분리 함수다. 기존 원문 선택 시험과 자동 결합하지 않았고, 앱 서비스·라우트에도
연결하지 않았다. 실제 문서 소속 확인은 평가 호출자가 수행한다. 제품의 revision·동의·
취소/대화 저장 가드를 대신하지 않는다. 출처 간 문맥 제거에 따른 품질 손실도 남는다.

## 합성 재현과 자동 검사

같은 재서술 문장에 잘못된 실제 출처 ID를 붙인 기존 경로는 수치 검사에서 거부된다.
출처 고정 시험은 올바른 원문만 입력한 뒤 같은 문장을 해당 원문의 검토 후보로 반환한다.
다른 lookup 청크에 수치가 있어도 후보의 검증 근거로 사용하지 않음을 확인했다.

- 새 단위 **61개**, 관련 회귀 **156 passed**, 0.63초. Ruff·mypy 132개 소스 통과.
- 최종 전체 API: **1,644 passed / 4 skipped**, 119.05초.
- 최초 버전 전체는 **1,641 passed / 4 skipped**, 120.21초였다. 이후 등급 표기 지침과
  회귀 3개를 추가하여 최종 상태로 다시 검사했다.
- 최초 Ruff의 테스트 한 줄 길이 초과를 줄바꿈으로 수정했다. 기존 접근 불가 캐시 폴더와
  Starlette/httpx 경고는 그대로다. 테스트를 건너뛰거나 검사 조건을 완화하지 않았다.
- 취소·deadline·입력 변경·숨은 원문·ID 위조·잘린 전송·출력 초과·보류/상충·숫자 변환을
  검사한다. 원문·해시·좌표 스냅샷과 외부 코드의 결과 객체 변경으로부터 입력을 보호한다.
- 합성 반례에서는 같은 청크 안 A/B형의 수치를 서로 바꾼 문장이 기존 어휘/수치 검사를
  통과했다. 이 알려진 한계를 테스트로 기록했으며 후보를 의미상 검증된 답변으로 승격하지 않는다.
