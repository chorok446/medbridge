# Q&A 스트리밍 동일 주장 중복 제거 — 2026-09-09

## 재현과 수정

- [설치본 검증](windows-pr7-validation-20260909-dc27530.md)에서 짧은 질문의
  동일 문장·동일 출처가 12회 저장·표시됐다.
- 비스트림 검증은 같은 문장을 제거하지만 스트리밍 경로는 검증된 모든 claim을
  바로 append·emit·checkpoint했다. 모델의 반복 출력이 그대로 남는 경로 차이다.
- 검증 후 `(문장, 출처 청크 ID 집합)`이 이미 채택된 경우만 건너뛴다.
  최초 정상 주장과 추가 출처를 보존하고, 출처 순서·동일 ID 반복은 구별하지 않는다.
  문단 번호가 다른 원문 인용은 문장이 다르므로 유지한다.
- 수치·극성·인용문 검증은 그대로다. 거부된 이전 복사본은 중복 목록에 넣지 않는다.
  중복 이벤트도 기존 취소·연결·revision 재확인 이후에 처리한다.
- 본문만 지우는 대신 emit과 draft 전에 제거해 화면·최종 본문·DB claim 및
  citation index/seq가 함께 일치하게 한다. 기존 저장 답변은 다시 쓰지 않는다.

## 회귀와 한계

- 새 통합 회귀는 잘못된 출처 복사본 → 정상 문장 12회 → 다른 문단 인용 순서다.
  수정 전 11개 초과 claim으로 실패했다. 수정 후 최종 2개만 출력·저장되고,
  checkpoint는 1개→2개, 인용 인덱스는 0·1, seq는 1·2임을 확인했다.
- 스트리밍 통합 테스트 22 passed. Ruff 및 mypy 126개 소스 통과.
  샌드박스 임시 디렉터리 거부는 테스트 준비 단계 오류였고, 권한을 갖춘 동일
  명령에서 실제 실패→수정 후 성공을 확인했다. 사용자 DB는 사용하지 않는다.
- 의미가 같지만 표현이 다른 문장, 같은 문장의 서로 다른 출처 집합은 병합하지 않는다.
  새 출처를 버리거나 스트리밍 출처 갱신 프로토콜을 바꾸는 대안은 채택하지 않았다.
- 긴 질문의 전체 보류는 별도 문제다. 설치본의 정확한 합성 청크를 읽기 전용으로
  가져온 provider 진단 3회에서, 원문 인용의 소개 문구도 어휘 검증에 거부됐다.
  문서 밖 정의도 함께 거부됐고 유효 claim은 매회 0개였다.
  provider 진단은 검색·DB 저장·GUI를 포함한 정식 평가가 아니다.
- 사용자 데이터·모델·설치된 앱은 변경하지 않았다. 새 코드의 전체 모델 평가와
  새 installer 검증 전까지 PR Draft / 출시 HOLD / 승인 파일 미생성을 유지한다.

셀프 리뷰: 중복 제거 한 목표에 한정했다. 인용 안전 검사와 최종 보류 정책은
완화하지 않았고 사용자 이력의 삭제·재작성이나 관련 없는 포맷 변경은 포함하지 않았다.
