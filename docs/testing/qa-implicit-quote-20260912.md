## 재현된 문제

직전 `088226f`의 첫 전체 모델 평가는 38/39였다.
`grounded_quote_without_expansion` 세 번째 실행에서 문서 밖 풀이가 supported로 남았다.
보존된 합성 DB의 claim은 원문을 따옴표 없이 앞에 반복하고
`…라는 문장에서` 뒤에 원문에 없는 설명을 덧붙였다.

문장 인용으로 인식된 부분은 0개이고 전체 토큰 12개 중 원문 공유 토큰이 5개여서,
원문 반복이 뒤의 설명까지 뒷받침하는 것으로 처리됐다.
이는 설명의 의학적 진위가 아니라 **문서 근거가 없는 내용의 검증 통과** 문제다.
[최초 실패와 합성 원문·토큰 진단](windows-pr7-classification-20260910.md)은 변경하지 않았다.

## 최소 변경과 적용 범위

- 문두의 `…라는/이라는 문장·구절·표현에서/은/는/을/를` 형태를 인용 후보로 식별한다.
  두 토큰 이상이며 공백 정규화·단어 경계 기준으로 실제 인용 출처와 일치할 때만 분리한다.
- 분리된 원문이 추가 설명의 어휘 비율을 채우지 못하도록 기존 인용 밖 설명 검사에 연결한다.
  앞부분을 제거한 별도 답변을 만들지 않는다. 설명이 미지원이면 원래 claim 전체를 거부한다.
- 출처에 있는 설명과 순수 인용은 유지한다. 출처 ID·본문·해시·좌표·수치·극성 검사,
  기존 한/영 교차 문자계 처리, 프롬프트·모델 옵션·검색·재시도 상한은 변경하지 않았다.
- 의료 용어 금지 목록을 제품에 추가하거나 평가 데이터·기대 상태·게이트를 완화하지 않았다.
- **범위 제한:** 특정 한국어 문두 인용 형태의 방어다. 다른 도입 형태·문장 중간의 원문 반복,
  모든 언어의 복합 주장, 일반 함의·의미 정확성을 해결하는 검증기는 아니다.
  문서 밖 설명을 전부 차단한다고 주장하지 않는다.

제품 파일 1개와 회귀 테스트 2개만
`9e47879e5012901ac9b6f57aa5131953cda6c83e`로 커밋했다.
프런트·설치기·DB 스키마·의존성 변경은 없다.
