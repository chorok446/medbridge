프롬프트·정답표·선택 규칙·재시도 정책과 제품 전송 코드는 변경하지 않았다.

- 평가 CLI에 `--diagnostics`를 추가했다. 기본값은 꺼짐이며 보고서 schema_version은 5다.
- 각 단계의 번호, 전체/독립/전체 가드 구분, 지역 판단에 대응하는 전역 묶음 번호,
  실제 요청 시작 여부, 진행 단계와 검증된 target/basis/conflict/status만 기록한다.
- 엄격한 기존 파서가 승인한 응답만 범주별로 복사한다. 원문·질문·이력·ID·경로·모델의 자유 텍스트·
  예외 메시지는 기록하지 않는다. 잘못된 응답은 범주까지도 기록하지 않고 실패시킨다.
- 예외 체인에서는 허용한 예외 종류와 실제 정수 errno/winerror만 남긴다. 최대 8개,
  순환/중복 차단, 숫자는 -65535~65535로 제한한다. 문자열의 10054 같은 표현을 코드로 추측하지 않는다.
  알 수 없는 예외 이름은 other_error로 바꾸고 억제된 예외 문맥은 노출하지 않는다.
- `native_request`는 HTTP 전송뿐 아니라 native 응답 envelope 검증도 포함한다.
  이 단계 이름만으로 소켓의 구체적 실패 위치를 단정하지 않는다.
- 중간 오류 시 그 전의 검증된 단계 기록만 보존한다. 최종 선택은 반환하지 않으며,
  해당 사례의 품질 수치는 null로 유지한다. 관찰 객체를 다시 쓰면 이전 기록을 비운다.
- 진단값은 선택 로직에 사용하지 않는다. 기본/지침/체크리스트/독립 전략의 계측 on/off에서
  결과·모델 payload·옵션·요청 수가 같은지 자동 검사했다. 계측의 시간 비용이 0이라는 주장은 아니다.

```powershell

exit $LASTEXITCODE
```

이번에는 실행하지 않았다. 전체 게이트의 사례 필터나 기대값을 바꾸지 않는다.
