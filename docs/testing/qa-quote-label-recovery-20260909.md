## 수정과 안전 경계

- 로컬 Ollama의 정상 시도 버퍼를 기존 검증기로 보내기 전에 순수 인용 표기만
  복원한다. 모델 요청·네트워크 재시도는 그대로 수행하며 모델 호출을 생략하거나
  합성 평가의 정답을 하드코딩하지 않는다. 특정 의학 문장·문단 수에 의존하지 않는다.
- 한국어의 명시적 `문단 N부터 문단 M까지 ... 원문을 인용해 주세요` 요청에 한정한다.
  `~`·`-` 범위도 허용한다. 복수 범위·역순·20개 초과·추가 장/쪽 한정·부정 요청·
  다른 요청 문법은 처리하지 않고 원래 이벤트를 유지한다.
- 검색된 청크 본문에 있는 실제 `문단 N.` 또는 `문단 N:` 블록만 사용한다.
  모든 요청 번호가 있어야 하며 같은 번호의 내용이 다르면 복원하지 않는다.
  제목·쪽수 메타데이터나 사용자 질문에서 새 원문·번호를 만들어 붙이지 않는다.
- 모델의 인용 문장과 실제 인용한 청크 ID가 각 문단을 뒷받침해야 한다.
  비교는 공백·줄바꿈과 마지막 마침표만 정규화한다. 문장이 다른 문단을 모델이
  인용하지 않았다면 내용을 보충하지 않는다. 번호 없는 동일 문장은 실제로 같은
  본문을 가진 요청 문단들의 표기를 복원할 수 있다.
- 이미 번호가 붙은 인용은 그 번호에만 대응시킨다. 완전한 근거가 확인되면
  요청 번호 순서로 원문 표기를 복사하고 실제 인용된 유효 출처 집합만 보존한다.
  잘못된 출처나 설명을 정상 인용으로 바꾸지 않는다.
- 일반 설명·문서 밖 설명은 그대로 기존 검증기로 보낸다. 수치·부정·출처·어휘
  검증, 모델의 보류·상충 상태와 기존 final 부재 처리 정책은 변경하지 않는다.
- 600자 claim·20개 claim·4,000자 본문 상한 안에서만 복원한다. 완료되지 않은
  시도나 취소된 시도는 복원·재생하지 않는다. 외부 API 스트림과 비스트림 경로는
  변경하지 않아 새 버퍼 지연을 추가하지 않는다.
- 사용자 DB·문서·설정·모델 파일은 변경하지 않는다. 제품에 원문 로깅을 추가하지 않는다.
