## 수정과 안전 경계

- 로컬 Ollama의 정상 시도 버퍼를 기존 검증기로 보내기 전에 순수 인용 표기만
  복원한다. 모델 요청·네트워크 재시도는 그대로 수행하며 모델 호출을 생략하거나
  합성 평가의 정답을 하드코딩하지 않는다. 특정 의학 문장·문단 수에 의존하지 않는다.
- 한국어의 명시적 `문단 N부터 문단 M까지 ... 원문을 인용해 주세요` 요청에 한정한다.
  `~`·`-` 범위도 허용한다. 복수 범위·역순·20개 초과·추가 장/쪽 한정·부정 요청·
  다른 요청 문법은 처리하지 않고 원래 이벤트를 유지한다.
- 검색된 청크 본문에 있는 실제 `문단 N.` 또는 `문단 N:` 블록만 사용한다.
  모든 요청 번호가 있어야 하며 같은 번호의 내용이 다르면 복원하지 않는다.
  제목·쪽수 메타데이터나 사용자 질문에서 새 원문·번호를 만들어 붙이지 않는다.
- 모델의 인용 문장과 실제 인용한 청크 ID가 각 문단을 뒷받침해야 한다.
  비교는 공백·줄바꿈과 마지막 마침표만 정규화한다. 문장이 다른 문단을 모델이
  인용하지 않았다면 내용을 보충하지 않는다. 번호 없는 동일 문장은 실제로 같은
  본문을 가진 요청 문단들의 표기를 복원할 수 있다.
- 이미 번호가 붙은 인용은 그 번호에만 대응시킨다. 완전한 근거가 확인되면
  요청 번호 순서로 원문 표기를 복사하고 실제 인용된 유효 출처 집합만 보존한다.
  잘못된 출처나 설명을 정상 인용으로 바꾸지 않는다.
- 일반 설명·문서 밖 설명은 그대로 기존 검증기로 보낸다. 수치·부정·출처·어휘
  검증, 모델의 보류·상충 상태와 기존 final 부재 처리 정책은 변경하지 않는다.
- 600자 claim·20개 claim·4,000자 본문 상한 안에서만 복원한다. 완료되지 않은
  시도나 취소된 시도는 복원·재생하지 않는다. 외부 API 스트림과 비스트림 경로는
  변경하지 않아 새 버퍼 지연을 추가하지 않는다.
- 사용자 DB·문서·설정·모델 파일은 변경하지 않는다. 제품에 원문 로깅을 추가하지 않는다.

## 자동 검증

- 새 helper 계약 테스트는 구현 전 모듈 미존재로 실패했다. 별도의 기존 native
  provider 동작 회귀는 번호 없는 문장이 그대로 나오는 assertion 실패를 재현했다.
- 복원 단위 31개 통과. 다른 번호 범위, 역순 모델 출력, 서로 다른 본문, 모호한
  원문, 누락·잘못된 출처, 출력 상한, 부정 요청, 모델 보류·상충, 취소와 외부
  스트리밍 미변경을 포함한다. 입력 이벤트를 제자리에서 변경하지 않음도 확인했다.
- 기존 인용 근거·스트리밍과 초기 복원 테스트의 집중 실행은 123 passed였다.
  이후 범위·취소 회귀를 추가했다. 스트리밍 통합 테스트는 24 passed / 7.34초다.
- 통합 회귀는 합성 PDF 업로드·추출·검색 후 native 프레임으로 번호 없는 원문을
  반복한다. 최종 문단 1~12의 text·출처·인덱스·DB 저장·draft 정리, 문서 밖 설명
  차단과 explicit insufficient_evidence 시 최종 claim 0개를 검사한다.
- Ruff 및 mypy 127개 소스 통과. Ruff의 기존 pytest 임시 디렉터리 2개 읽기 권한
  경고는 남았으며 해당 경로를 삭제하거나 검사 설정을 완화하지 않았다.
- Windows Python 3.13.14의 전체 API 검사는 **1,165 passed / 4 skipped**,
  기존 Starlette 경고 1개, 106.59초다. 사용자 DB 대신 테스트 전용 임시 DB를 썼다.
  이 결과를 CI Python 3.12나 새 installer의 통과로 확대하지 않는다.

## 남은 한계

- 문단 경계가 빈 줄로 구분되고 명시적 표기와 문장 끝이 있는 인용만 복원한다.
  청크 밖 문단을 추가 검색하거나 PDF 전체 문단 경계를 다시 계산하지 않는다.
  문장 끝 기호만으로 원래 PDF 문단 전체가 보존됐다고 증명할 수는 없다.
- 바꿔쓰기·소개 설명·인용 없는 주장이나 모델이 다른 본문을 인용하지 않은 경우는
  그대로 남는다. 의미적 함의 판단기나 모든 언어·문서 형식의 완전성 해결이 아니다.
- 고정 커밋 전체 모델 평가와 새 CI installer의 실제 GUI 검증은 별도 기록한다.
  새 코드의 installer 검증 전까지 PR Draft / 출시 HOLD / 승인 파일 미생성을 유지한다.

셀프 리뷰: 문서 밖 설명을 제거해 평가를 통과시키거나 검증 임계치를 낮추지 않았다.
정상 시도의 동일 인용 표기 복원 한 목표로 한정했고 UI·DB 스키마·의존성 및
관련 없는 포맷 변경을 포함하지 않았다.
