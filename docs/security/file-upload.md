# 파일 업로드 보안 (개발 문서)

## 검증 순서 (모두 서버 측)

1. 스트리밍 크기 제한 — 초과 즉시 중단 (`FILE_TOO_LARGE`)
2. 실제 시그니처 검사 `%PDF-` — 확장자·클라이언트 MIME은 신뢰하지 않음
3. SHA-256 계산 + 프로필 내 중복 탐지
4. 원자적 저장: 같은 디렉터리 임시 파일 → `os.replace` (실패 시 임시 파일 정리)
5. 비동기 검증: pypdf 파싱 → 암호화 거부 → 페이지 수 → 구조 손상 → 저장본 해시 재확인

## 경로 안전

- 저장 키는 `documents/{uuid}/original.pdf` — 사용자 파일명은 DB 메타데이터로만 보존
- 모든 경로는 앱 데이터 루트 기준 `resolve()` 후 루트 밖이면 거부 (경로 순회 방지, 테스트 강제)
- 사용자 데이터는 저장소·설치 경로 밖 OS 앱 데이터 디렉터리에만 저장

## 접근 통제

- sidecar는 127.0.0.1에만 바인딩, Tauri가 발급한 토큰 없는 요청은 401
- 문서 API는 전부 로컬 프로필 소유권 검사를 거침 — 요청의 user_id는 무시 (테스트 강제)
- 타인 문서는 존재 여부를 숨기기 위해 404로 응답

## 정보 노출 방지

- 내부 예외·스택·경로는 응답과 GUI에 노출하지 않음 (500은 일반 문구 + correlation id 로그)
- 로그에는 문서 ID·correlation id만 기록, 파일 내용·개인정보 기록 금지
- 개인정보 포함 가능 파일은 업로드 전 사용자 확인 체크 필수 (외부 AI 전송은 Sprint 2+에서도
  마스킹 검토 완료본만 허용하는 설계 유지)
